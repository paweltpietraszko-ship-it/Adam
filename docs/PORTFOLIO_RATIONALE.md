# Why this repository is presented this way

This repository is intended to show practical experience with model evaluation rather than conventional software-engineering polish.

The presentation emphasizes:

- repeated failure analysis
- side-by-side model comparison
- grounding and instruction-following problems
- adversarial testing and edge cases
- human-in-the-loop review
- deterministic backend controls around probabilistic models
- regression-oriented fixes after failures

That emphasis matches the kinds of tasks commonly requested in current LLM evaluator and model-quality roles: applying rubrics, identifying recurring failure modes, documenting edge cases, comparing model outputs and explaining why a result is wrong even when it looks plausible.

The codebase remains intentionally close to the real project history. It has not been rewritten to create the appearance of independent software-engineering expertise that the project owner does not claim.
